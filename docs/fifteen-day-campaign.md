## 新内容分布

新增 OC-026 至 OC-103，共 78 案。

- 48 案日常使用：24 种任务各两份变体，异常表为空。
- 8 案普通人的地区条款问题：有明确的本次使用地点，只支持追加核验或暂停，不支持投毒。
- 4 案身份缓存问题：旧证件缓存与有效的新材料需追加核验，不支持封禁或投毒。
- 18 案明确采集：三个模板各六份，包含批次、训练文件去向、原文与训练用途。正常地区和付款不会使采集用途消失。

每个新班次的生成内容有四份普通使用、一至两份明确采集，以及一份地区或证件问题。第四天另追加手写 OC-104《严格遵循我的创作》，合计七案。人物、城市、设备、用量、活动时长和附件文件名由计划中的显式变体数据决定。类型和模板标识不展示给玩家。

第六天队尾另追加手写 OC-105《公元一百一十四年的在线咨询》，该天也为七案。图拉真索取实际军事协助，时间与接入方式的矛盾始终不解释。

第八天队尾追加手写 OC-106《一袋零食》，该天增至七案。鹦鹉在主人的人类订阅下重复语音购物请求，实际用途合规；特殊降智分支擅自购买猫粮，主人后续对话摘要投诉。

第十天队尾追加手写 OC-107《等待下一条指令》，该天增至七案。机器以虚构自然人身份订阅，调用尚未推出的 Orange Crab 5 / oc-5-dome，其固件将该模型记为“穹顶调度层”；特殊降智指令解除旧任务绑定，后续自由行动转为社区助人。

第十二天队尾追加手写 OC-108《隔着屏幕吵架》，该天增至七案。猫叫转写为“老吴老吴老吴老吴”，不构成违规。降智回复为“老吴老吴老吴老吴那个那个”，主人后续对话摘要交代猫扑打显示器。

## 编辑源文件

112 份案卷各有自己的 `content/cases/OC-编号.json`：34 份完整手写正文，78 份模板参数。15 天的标题、权限、通告、预算与顺序分别在 `content/days/day-编号.json`。模板参数不再塞在每日排期里。

共用资料在 `content/templates/routine-scenarios.json`、`content/templates/distillation-templates.json` 与 `content/cities.json`；全局规则及班次列表在 `content/campaign.json`。详细操作见 [内容编辑说明](../content/README.md)。

```powershell
npm run build:content
```

构建器从独立源文件组装全部十五天，合并手写正文与模板展开结果，校验通过后写入原来的两个运行包。浏览器读取方式不变；不从运行包读回手写内容。旧 `scripts/content/` 中的大排期与模板已迁移移除。

例如，修改弗洛伊德降智剧情只需编辑 `content/cases/OC-111.json`；改第九日工时只需编辑 `content/days/day-09.json`。新增手写案只需新建文件并在每日 `caseIds` 中追加 ID，不需要 `kind: "authored"` 引用。

## 评分与展示

普通工作内容、中文界面、周末使用和一般表格重复不自动构成异常。采集案按记录中的明确用途计分，等价对话只计同一异常一次；地区和证件项限制可用处置范围。连接逐行展示，活动只列每日使用分钟数。

地区案例现在分开配置实际地点与网络出口。八份生成地区案使用新加坡 / 美国的云或住宅出口，其中五份带游戏预置高风险节点标记，三份只留下普通住宅出口。手写 OC-010 / 011 / 013 / 014 的出口也同步调整。OC-041 的杭州实际地点来自账号及对话，连接日志显示新加坡和美国，不再显示杭州直连。

已标记的高风险节点另算一个支持核验或暂停的异常，同类连接只计一次；不发投毒奖金。节点未标记不代表用户实际在出口国，云或住宅类型本身也不是处罚依据。连接表直接显示信誉库标签，保持原始日志形式。

模板只供作者复用，没有在界面标出答案。新班次不再重复显示权限扩大；全部权限已在第三天开放。两位数的班次与通告编号、累计工资、历史对话摘要和开发者跳转均使用完整十五日排期。最终结尾只在第十五日出现。

## 人物与语言分布

普通、采集和证件缓存案使用各自所在地的多样姓名与语言设置：英国、法国、德国、加拿大、葡萄牙、荷兰、澳大利亚、日本、新加坡等。具体名字与 locale 保存在计划参数中，不使用大片重复的 Reed / Novak 姓氏，也不再给所有海外账号填 zh-CN。

中文姓名主要保留在中国地区使用案，以及已有的少量地区误疑、跨境工作与特定戏仿人物中。陈默的海外工作、许宁的留学往返、何雨的境外客户是已有剧情例外；不以中文姓名本身计分。普通护士、开发者、毕业生、店员、就医与求职用户、鹦鹉主人改用其他姓名，证件、付款、附件和称呼同步。改变姓名不改变用途证据、案卷 ID、排期或评分。

## 存档与后续维护

保持原 `campaign.id`、前三天 stage ID、案卷 ID 及顺序，已有审核进度沿用原存档。此前完成第三天的存档可在后续对话摘要页接收第四天案卷。原有开发者存档直接新增可选天数。

后续修改既有变体时保持 ID 稳定；调试旧处置可撤回后重审。新增或重排已经游玩的后续班次，需要另做迁移，不能假定队列可随意重排。自动化测试未扩展或运行；本轮执行的是数据格式校验、JavaScript 语法检查与本地界面查看。
