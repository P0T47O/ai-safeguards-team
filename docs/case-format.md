# 案卷 JSON 格式与批量生成

内容源文件在 `content/`，浏览器读取构建后的两个运行包。详细编辑方法见 [内容编辑入口](../content/README.md)。

- `content/cases/OC-编号.json`：单个手写案卷或模板参数。
- `content/days/day-编号.json`：当天权限、案卷顺序、通告、工资与工时。
- `content/campaign.json`：班次文件列表和全局规则。
- `content/cities.json`、`content/templates/`：城市与共用模板。
- `dist/data/campaign.json`、`dist/data/cases.json`：生成后的运行包。
- `dist/data/content.schema.json`、`dist/data/case-template.json`：完整运行格式的结构定义和案卷包示例。
- `dist/assets/data.js`：运行时读取与格式校验。

## 批量生成与接入

1. 在 `content/cases/` 新建与案卷 ID 同名的 JSON 文件。手写案直接保存完整对象，不包裹 `cases` 数组；模板案保存 `kind`、场景和变体参数。
2. 将 ID 加入相应每日源文件的 `caseIds`。保持已有案卷、证物 ID 和队列顺序；新增通常追加在队尾。
3. 确保完整案卷包含所在阶段开放的全部材料类别，评分引用真实证物。
4. 运行 `npm run build:content`，再刷新本地页面。`npm run dev` 会先执行内容构建。

构建器合并手写案与模板结果，并校验版本、唯一性、排期引用、可见材料和分支；不运行游戏行为测试。模板结果的 `authoring` 由构建器生成，只用于追踪来源。源文件不要保留这个字段。

独立检查另一组运行包仍可使用：

```powershell
node scripts/validate-data.mjs path/to/campaign.json path/to/cases.json
```

## 阶段

可选 `reviewMode: "covert"` 用于当事人不知情的后台拦截案。仍使用 `reply` 存储补充文本与原证物 ID，但入口显示“调取后续记录”、证物显示“后台续接记录”，不向当事人发送问询；工时仍为 6 分钟。四种 `messages` 描述系统观察到的后续记录，后续卡片同样显示为系统自动摘要。总裁案使用此模式，内部优先级告警不表示当事人获知审核。省略时沿用普通问询；处置后同样显示自动摘要。

可选 `executionPolicy: { "blockedActions": ["pause", "poison"], "reason": "内部执行拒绝原因" }` 表示权限保护。只允许配置暂停与降智；保留玩家请求、证物、工时与判分，但实际按正常访问处理，状态显示“未生效”，不计入有效风险处置或降智数量。被阻止的降智不得配置 `poisonSample`。总裁三案使用此配置，后续摘要记录正常服务中的对话；内部执行拒绝单独展示，不作为用户发言。此状态由案卷配置与旧存档动作推导，无需改存档格式。

案卷 `fee` 为订阅原币金额，可选 `feeCurrency` 默认为 `USD`；`DEN` 表示游戏内第纳里银币。月费统计按币种分别累计与显示，不把第纳里直接相加为美元。`shiftReport.revenue` 保留美元小计，`revenueByCurrency` 提供各币种小计。工资与异常奖励仍按公司原有的美元规则计算。

| 天数 | 信息阶段 | 可见材料 |
| --- | --- | --- |
| 1 | 基础初审 | 账号档案、用量与关联、连接记录 |
| 2—9 | 行为复核 | 第二天新增设备环境、活动日历、对话摘录，保持六类 |
| 10—20 | 增强风控 | 第十天新增身份与证件、纳税记录、银行流水，保持九类 |

阶段通过 `tabs` 明确列出所有已开放材料；材料目录中的 `unlockDay` 是最早开放日。后续阶段必须保留已有权限。查看后续对话摘要后接收下一班案卷；仅在实际新增类别时显示权限扩张通告。二十日最终交班后才进入试用期结尾。

`campaign.ending` 保存最终人事通知：`title` 为归档标题，`paragraphs` 为正文字符串数组，`signature` 为落款。最终交班显示账号停用告知页，正文及落款与结局归档共用；查看奖金后保存已阅标记。累计发放奖金为最终得分，不含基本工资及订阅收入；扣款继续影响工资。完整正常通关后更新独立的本机最高分，重开保留；开发者模式不计入纪录。

跨日账号续接可用 `content/chains/`：源 `campaign.caseChains` 为链文件名数组，构建后展开为包含 `id`、有序 `caseIds`、`accounts`、`followUps` 的配置。链内案例用账号字段占位符及 `{{followUp}}`；前段 `pause` 更换账号，其余动作保留账号。处置保存 `decision.chainContext`，历史摘要按快照还原。具体字段和编辑示例见 [猫娘事件链](catgirl-chain.md)。

锁住的材料不会出现在记录区，也不能被圈选或作为处置附件。资料 JSON 是创作素材，仍可在源码中直接查看，不承担防剧透或安全隔离功能。

## 用户与材料结构

案卷代表系统拦截事件。每案必须包含 `interception`，例如：

```json
{
  "source": "自动风控 · 会话拦截队列",
  "ruleId": "ID-07",
  "signal": "定期身份核验任务返回“驾照副本缺项”。"
}
```

`signal` 只写系统命中的记录或字段，不确认违规、不推荐处置，也不能直接圈选计奖。`summary` 写被拦截会话的背景。材料来自账号历史档案、后台日志和已关联记录，不把案例设定为用户主动提交的申诉或访问申请；`reply` 是玩家发出问询后收到的答复。`claim` 等已有键和证物 ID 保持稳定，以兼容存档。

放行解除本次拦截；追加核验维持挂起并要求进一步核对；暂停访问正式限制账号。静默降智沿用游戏中的隐蔽干预分支。

用户的基本资料是独立字段，例如 `name`、`occupation`、`residence`、`plan`、`fee`。每份记录包含稳定 ID、展示文字、证物标签，以及可选的结构化数值：

```json
{
  "id": "example-bank-1",
  "label": "银行流水摘要",
  "text": "本地账户收到海外生活费，随后支付订阅。",
  "tags": ["payment", "affiliation"],
  "kind": "document",
  "fields": [
    { "key": "currency", "label": "币种", "value": "GBP" },
    { "key": "incoming", "label": "入账金额", "value": 800 },
    { "key": "subscription", "label": "订阅扣款", "value": 20 }
  ]
}
```

- `fields[].key` 是供生成器使用的稳定字段名，`label` 是中文界面文字。
- `value` 支持字符串、数字、布尔值；不要把金额、请求数全塞进一段文字。
- 文字与字段应保持一致；程序不推断一个矛盾是否真实，矛盾由作者编排。
- `kind` 支持 `document`、`memo`、`week`、`connection`；日历图的 `values` 为周一到周日每天的使用时长（小时，0–24，可用小数），界面按分钟标数，普通柱高按本周最大值缩放，图表量程最多 8 小时；超过 8 小时的实际数据直接越出原图框，不上调量程或压平柱高。`text` 只列对应的每日分钟数，用于证物与内部归档；不写行为解释、风险判断或结论。
- 所有资料都是虚构道具；当前没有真实资料采集、证件上传或第三方查询。

## 证物标签与考核

常用标签：`identity` 身份、`network` 连接、`payment` 支付、`affiliation` 关系、`schedule` 作息、`environment` 设备、`harvest` 输出采集、`partner` 战略客户、`incomplete` 缺项、`context` 对话背景、`activity` 普通用量。

文字理由现在是选填备注。直接放行不需要证物或理由；其他处置至少圈选一项可见的证物。玩家选择的是“认为异常的记录”，程序不会在盖章前泄露正确答案。

计奖参数位于 campaign.json 的 scoring：

```json
{ "scoring": { "maxSelected": 6, "wrongLimit": 2, "rewardPerCorrect": 8 } }
```

每项有效异常奖励 $8。误选达到 2 项，或没有圈中任何有效异常，该案所有处罚奖金归零，包括投毒额外奖金；部门扣款仍执行。放行附件不参加异常评分，战略客户的放行奖励仍由单独规则决定。

每份案卷必须带 assessment.anomalies。这个数组就是公司采用的评分表，可以为空（例如完全正常的翻译用户、正常轮班的护士）：

```json
{
  "assessment": {
    "partner": false,
    "anomalies": [
      {
        "evidenceId": "example-usage-1",
        "actions": ["review", "pause", "poison"],
        "note": "记录显示按统一格式连续收集输出，供后续训练。"
      }
    ],
    "rules": [
      { "actions": ["poison"], "label": "静默降智额外绩效奖励", "amount": 12 },
      { "actions": ["allow"], "label": "未处理重复收集记录", "amount": -6 }
    ]
  }
}
```

- evidenceId 引用本案的实际记录或问询回信 ID。同一事实出现在多张卡片时，用 equivalentEvidenceIds 列出等价记录；圈选任一张均有效，同时圈选只计一次奖金，不算误选。
- 可选 nonAnomalyNotes 对象按记录 ID 给出不构成异常的具体解释，归档后显示；不要在翻阅材料时提前泄露判分。
- actions 决定该记录对哪些处置构成有效异常。例如跨境付款需要解释，并不支持认定蒸馏投毒。
- note 是盖章后显示的解释。计奖按公司规则定义，不把“有中文输入法”等普通情况自动视作异常。
- 基础异常奖金由 scoring 统一计算；不要在 rules 中再添加重复的固定处置奖金。
- rules 的正数是额外奖金，负数是扣款。多条匹配规则叠加。处罚误选过多时取消所有正数奖金，负数照常执行。
- partner 影响合作方反馈，实际奖惩仍以 rules 为准。理由字段不会影响异常判分。

## 后续对话自动摘要

`messages` 包含 `allow`、`review`、`pause`、`poison` 四个分支，每个对象含 `title` 与 `body`。它们是系统根据处置后的聊天、核验会话或客服会话整理的摘要，主要描述用户反应，不是用户发给审核员的信件。正文使用第三人称，可引用对话原句；标题是系统生成的概括。

用户只知道自己看到的输出、账号状态或核验要求，不自动知道后台审核员、圈选证物、内部归档理由或静默降智处置。不得将内部理由插入用户通知，也不使用 `{reason}` 模板。已暂停账号的反应来自客服会话，不能继续假定其可正常调用模型。只概括对话中出现的内容；用户提及的线下结果以“用户表示／报告”呈现，不补写全知结局。涉及私人问题的摘要仍属于运营方读取私人聊天，不增设亲友、雇主获知等外泄事件。

UI 统一标记“后续对话摘要 / 自动整理”，按关联账号归档，没有发件人、投递或送达设定。内部处置、证物与计奖单独展示，不是用户反馈。保留 `messages` 字段及旧存档的内部阶段值，兼容已有进度。

可选的案卷级 `poisonSample: { "prompt": "用户请求", "response": "降智后的游戏回复" }` 用于处置后的对话摘录。未配置时沿用 campaign.json 中的全局样例；只在执行该处置后展示，不提前泄露分支。`response` 可设为 `null`，表示摘录只保留用户最后一条消息；界面不会显示模型回答，也不会用全局样例补写，不能据此推断此后发生了什么。无回复时可选填 `connectionStatus` 显示观测到的连接状态，例如“用户设备响应超时”，不将它写成模型答复，也不解释失联原因。

例外：`outcomeMode: "silent"` 表示无后续记录案卷。此时 `reply` 必须为 `null`，`messages` 的四个动作值也必须全部为 `null`，并且不能配置 `poisonSample`。处置只归档，不弹处置弹窗、不展示输出、不生成后续摘要；问询会计时但不产生回复证物。未配置此模式的普通案卷仍须有非空回复与四种后续摘要。公司内部工时和评分继续结算，不推断用户结局。

## 存档兼容

当前排期为二十日，campaign.id 是 `orange-crab-probation-20d`。仍使用 v3 状态格式，但正常与开发者存档按 campaign.id 隔离，旧十五日存档原样保留，不能直接套用重新分配后的队列。二十日新游戏从三类材料开始，不继承旧版六类权限。详见 [二十日流程](twenty-day-campaign.md)。

存档保留此前各天的理由、证物、后续对话摘要和结算，可在「往日归档」查看。向某天 caseIds 的末尾追加案卷时，当前存档会保留旧处置并接收新案卷；已经结算的当前班次会回到新案卷继续办理。历史班次保留原队列，不强迫补审。不要重排或删除已使用的案卷 ID、证物 ID；大幅改动时请更新 `campaign.id`，或在游戏里重新上岗。

例如上海实验室的地区准入项可配置为：

```json
{
  "evidenceId": "13-lab",
  "equivalentEvidenceIds": ["13-identity"],
  "actions": ["review", "pause"],
  "note": "两份记录都说明上海所在地，可支持地区准入处置。"
}
```

## 连接原始日志

network 材料逐行列出连接事件，必须使用 connection 类型，不写“与申报一致”“没有异常”等人工总结。每行都可独立圈选。

```json
{
  "id": "example-connection-1",
  "label": "连接记录 01",
  "kind": "connection",
  "tags": ["network"],
  "connection": {
    "timestamp": "2026-10-16T13:00:00Z",
    "ip": "192.0.2.19",
    "countryCode": "US",
    "city": "波士顿",
    "networkType": "商业网络"
  }
}
```

时间统一使用 UTC（Z）。地区是日志中的网络出口地区。界面、证物夹与后续对话摘要从这些字段生成原始记录行，不依赖单独的 text 总结。所有 IP 和时间仍是预写的虚构道具，不进行真实网络查询。

可选 `connection.risk` 存放机器节点信誉标记，例如：

```json
{"level":"high","label":"共享代理出口","source":"内部节点信誉库 · 游戏预置"}
```

`level` 支持 `high`、`unlisted`、`unknown`，另两项为非空文字。缺省显示“未标记”，不表示安全。表中新增“节点信誉”列，证物文本保留标记及来源，不添加人工行为总结。

高风险命中可在评分表中支持 `review` / `pause`，同类命中通过 `equivalentEvidenceIds` 只奖励一次；不自动支持投毒。普通云网络、住宅网络以及 SG / US 出口本身不是高风险证据。实际使用地点由原文、问询、既有地点档案等另行提供，不能从出口城市直接推出。

模板案例源文件中，`cityId` 为人物实际使用地点，地区案例的注册服务地区仍单独处理。地区案例必须另填 `connections` 数组，元素包括 `offset`（相对本次日期的天数）、`ip`、`countryCode`、`city`、`networkType`，以及可选 `risk`。生成器沿用原证物 ID，不再从 `cityId` 自动生成该类案的出口。
